## 2026-08-22 1553 视频号第一版产品契约与前台边界

决策：無涘 ｜ 记录：Codex

- 视频号处理必须复用现有批量扫描链路，自动点开、取链接并关闭；前台占用不得随视频时长增长，不允许静默退化为完整播放。
- 第一版最终笔记产物定为「原始链接 + 高质量摘要 + 关键要点」；完整逐字稿可作本地临时中间产物，但不默认写入笔记。
- 元宝总结不作为可信正文来源。当前建议的元宝登录态只承担腾讯域内短链解析凭据；该技术路径尚待单卡登录后验证，不视为已定生产依赖。

理由：用户需要的是可后台批处理、可回看且信息密度高的知识条目，而不是按视频时长占用电脑，或依赖无法复核的第三方摘要。

## 2026-08-22 1642 视频号后台链路定案并通过单卡验收

决策：無涘（授权一次性登录元宝；明确不采用元宝总结，内容由本链路分析） ｜ 记录：Codex

- 元宝独立 profile 只用于把公开 `/sph/` 分享链接解析为腾讯临时凭据；媒体由视频号官方 feed API 获取，元宝不接收逐字稿或摘要任务。
- 媒体下载后由本机 V2T Qwen3-ASR 转写；逐字稿只作临时中间产物。Codex 按固定 JSON Schema 生成高质量摘要和 3–8 条要点，最终笔记写入既有 Obsidian Clippings 目录。
- `collect` 默认在微信扫描结束后继续后台处理视频号；前台 viewer 关闭后用户可立即继续使用电脑。成功任务幂等跳过，失败必须留下阶段与非空错误码。
- 完整视频、WAV 和逐字稿默认在任务结束后删除；manifest 不保存 token、媒体签名 URL 或逐字稿正文。

理由：真实 5 分 28 秒单卡证明该链路无需完整播放即可得到可验证的 601 字摘要与 8 条具体要点；同时满足“不抢电脑”“不信任元宝总结”“不长期保存完整视频”和“失败可辨认”四个约束。
